# R0.7A Architecture v0.2 Migration Audit

**Status:** ACTIVE MIGRATION AUDIT  
**Audit date:** 2026-08-11  
**Planning baseline:** A0 accepted/frozen  
**Audited implementation baseline:** R0.1–R0.6 on `main` before R0.7A feature migration

## 1. Audit purpose

R0.7A does not add new creative intelligence. Its job is to make the already-working R0.1–R0.6 machinery truthful under Architecture Contract v0.2 before R0.7B+ expands product behavior.

Audit question:

> Which existing code may be retained, which code needs compatibility migration, and which historical bootstrap seams must be neutralized before v0.2 features depend on them?

## 2. Executive verdict

The existing foundation is **architecturally salvageable and should be migrated, not rewritten**.

Strong seams worth preserving:

- `AssetIngestService` owns Asset creation;
- `ShotDetector` proposals remain separate from `ShotCatalog` identity commit;
- `UnderstandingService` owns `ShotAnalysis` revisions;
- provider output already follows Proposal → deterministic normalization → owner commit;
- `ShotIndex` is already explicitly rebuildable/non-authoritative;
- SQLite repositories persist immutable exact revisions without claiming semantic ownership;
- `ArtifactStore` is already content-addressed and integrity checked;
- external heavy runtimes remain optional instead of contaminating the base environment.

The migration pressure is concentrated in six areas:

1. millisecond integer time authority;
2. Asset origin/usage/rights semantics;
3. SQLite schema/codec v1 compatibility;
4. `ShotAnalysis.embedding_ref` and future evidence classification;
5. legacy generic remote `MaterialProvider` bootstrap seam;
6. future-object stubs (`EditPlan`, `EDL`, `ReviewReport`) that must be upgraded before they receive real behavior.

No evidence supports a repository reset or a replacement architecture.

## 3. Findings by current implementation

### F-01 — `EntityEnvelope` lacks v0.2 derivation provenance

Current:

`src/video_editing_agent/domain/common/entity.py`

contains:

```text
id
revision
schema_version
status
created_at
created_by
```

Architecture v0.2 also requires durable revisions to preserve derivation lineage where applicable.

**Migration:** add an optional/defaulted exact-reference lineage field without breaking every existing constructor at once.

**Risk:** LOW if appended with an immutable empty-tuple default.

---

### F-02 — authoritative media time is still integer milliseconds

Current authoritative fields include:

- `Asset.duration_ms`;
- `Shot.source_start_ms` / `source_end_ms`;
- `Shot.duration_ms`;
- `EDLSegment.source_in_ms/source_out_ms/timeline_in_ms/timeline_out_ms`;
- understanding/sample timestamps in milliseconds;
- retrieval duration constraints in milliseconds.

This is internally consistent for R0.1–R0.6, but it is insufficient as the long-term canonical contract for VFR, derivative mapping and deterministic timeline rounding.

**Migration:** introduce `MediaTime(value, scale)` and `MediaTimeRange` first; then migrate ownership paths in controlled batches. Human/probe millisecond conversion helpers may remain for compatibility.

**Do not:** replace all integer-ms fields in one giant commit.

**Risk:** HIGH because Shot detection, sampling, indexing, probes and future EDL all touch time.

---

### F-03 — Asset `origin` conflates source origin and permitted usage

Current:

`domain/asset/model.py`

uses:

```text
origin: str
provenance.origin_type: str
```

and enforces equality.

`media/ingest/source.py` repeats the same relationship.

There is no `usage_role`, so the current model cannot represent the critical distinction:

```text
user local reference video
!=
user local editable footage
```

**Migration:** add typed Asset origin and typed usage role. Resolver eligibility must depend on usage role, not merely local storage.

Recommended active roles include concepts equivalent to:

```text
editable_visual_footage
reference_analysis_only
music
voiceover
sound_effect
logo_graphic
other_local_media
```

Exact names may be finalized in implementation, but role semantics are frozen by v0.2.

**Risk:** HIGH because this is a Product Constitution boundary.

---

### F-04 — current provenance is not yet a rights model

`AssetProvenance` currently records provider/source/license strings, which is useful provenance, but does not provide the v0.2 rights objects needed for:

- user rights attestation;
- provider `LicenseSnapshot`;
- warning/unknown/ineligible state;
- manual rights override;
- project/video/platform/territory/attribution evidence.

**Migration:** preserve `AssetProvenance`; add rights records as separate auditable value/artifact records rather than turning a string field into legal authority.

**Risk:** MEDIUM for R0.7A; HIGH before external music provider use.

---

### F-05 — SQLite schema v1 has no migration path

Current:

`storage/repositories/sqlite_database.py`

uses:

```text
SCHEMA_VERSION = 1
```

and accepts only database versions `0` and `1`.

Tables currently persist only:

```text
assets
shots
shot_analyses
```

This was correct for R0.4 but R0.7A now needs additive v0.2 records and old-project compatibility.

**Migration rule:**

```text
open database
→ inspect user_version
→ migrate forward explicitly
→ never rewrite historical semantic records silently
```

The schema migrator must be idempotent and transactionally safe.

**Risk:** CRITICAL. A broken migration can corrupt the most valuable existing project guarantee: revisioned local persistence.

---

### F-06 — record codec v1 rejects future/legacy mixed payloads too rigidly

Current:

`storage/repositories/record_codec.py`

uses one global `CODEC_VERSION = 1` and `_require_codec()` requires exact equality.

Current payloads also encode old Asset/Shot millisecond shapes.

**Migration:** implement version-dispatched decoding:

```text
legacy codec v1 → deterministic compatibility decoder
new codec v2    → v0.2 runtime model
```

New writes use v2 codecs. Legacy rows remain readable and immutable.

Where a v1 record lacks a v0.2 fact, compatibility mapping must be explicit and conservative rather than inventing permissive behavior.

Examples:

- legacy known local visual test/user footage may map to editable local usage only under documented migration policy;
- any legacy remote/generated visual origin must map to a restricted/non-Resolver-eligible state, never to editable fallback.

**Risk:** CRITICAL.

---

### F-07 — `ShotAnalysis.embedding_ref` is in the wrong semantic layer for v0.2

Current `ShotAnalysis` includes:

```text
embedding_ref: str | None
```

Survey V2 established embeddings as rebuildable retrieval representation, not authoritative Shot understanding.

**Migration:** stop writing embedding identity as a semantic ShotAnalysis fact. Move representation/model/index provenance to ShotIndex-side records.

Compatibility decoder may continue reading historical `embedding_ref` but should not use it as authoritative v0.2 semantics.

**Risk:** MEDIUM. Existing lexical retrieval does not depend on it, which makes migration easier.

---

### F-08 — `ShotIndex` ownership is already correct

Current:

`application/ports/shot_index.py`

explicitly states retrieval constraints are prefilters only and Resolver owns final eligibility.

Current `LexicalShotIndex` is rebuildable and uses exact Shot + latest analysis revisions.

**Decision:** RETAIN.

R0.7A should only migrate duration representation and prepare future derived embedding/index provenance. Hybrid retrieval belongs to R0.9, not R0.7A.

---

### F-09 — visual understanding ownership is already correct

Current `ProviderNeutralVisualUnderstandingService`:

```text
load exact Shot
→ deterministic sample plan
→ local frame extraction
→ ArtifactStore
→ provider proposal
→ deterministic normalization
→ ShotAnalysis owner commit
```

This matches v0.2's authority direction.

**Decision:** RETAIN.

R0.7A changes are limited to:

- MediaTime migration;
- artifact/evidence retention classification;
- later removal of embedding ownership from ShotAnalysis;
- preserving untrusted-provider/media-derived text semantics.

Do not redesign the service around Gemini or any provider.

---

### F-10 — ArtifactStore has integrity, but no retention/evidence class

Current `LocalArtifactStore` is content-addressed and validates SHA-256/size. That is valuable and should remain.

However a reference currently does not distinguish:

```text
rebuildable frame/cache
vs
expensive durable analysis evidence
vs
project output
```

**Migration:** add metadata/descriptor seam above content identity. Do not destroy content-addressed deduplication by baking lifecycle semantics into the content hash itself.

A single binary may be referenced by multiple roles; cleanup must respect the strongest retained role.

**Risk:** MEDIUM.

---

### F-11 — bootstrap `MaterialProvider` is constitutionally too generic

Current:

`application/ports/material_provider.py`

contains generic:

```text
MaterialQuery
RemoteMaterialCandidate
MaterialProvider.search(...)
```

It was created under v0.1 remote-fallback assumptions and is not constrained to audio.

No implemented R0.1–R0.6 business capability depends on remote visual acquisition.

**Migration:** remove/deactivate this generic visual-capable seam before future feature code can accidentally revive it. Future public discovery belongs under audio-specific provider contracts with Rights Gate semantics.

**Risk:** HIGH policy risk, LOW implementation risk if reference scan confirms no active imports.

---

### F-12 — `EditPlan`, `EDL`, `ReviewReport` are still bootstrap stubs

Current domain files are intentionally minimal:

- `EditSlot(slot_id, purpose)`;
- EDL segments contain integer-ms source/timeline positions;
- ReviewReport contains only stage/target/pass.

No mature Director/Resolver/Renderer behavior depends on these shapes yet.

**Decision:** this is favorable migration timing.

R0.7A should introduce the v0.2-compatible value contracts/seams before R0.7B–R0.12 turn these stubs into real product state.

Do not preserve underspecified bootstrap shape merely for compatibility with code that does not yet exist.

---

## 4. Constitutional conflict audit

### Active conflict found

The generic `MaterialProvider` port is the only obvious current source-level bootstrap seam that still expresses the old remote-material worldview strongly enough to be dangerous.

### Historical conflicts found but already non-authoritative

The v0.1.x documents contain:

```text
remote_allowed
remote_only
generated_allowed
remote_search_queries
remote/generated fallback decision types
```

A0 acceptance and Architecture v0.2 make these historical only. They must not be copied into new schema migrations.

### No current business path found that autonomously downloads/generated replacement visual footage

R0.1–R0.6 implemented local Shot/Asset/understanding/retrieval infrastructure, not stock-video fallback. Therefore migration is primarily preventive rather than a removal of working product behavior.

## 5. Recommended migration batches

Each batch is a separate coherent commit and must return green before the next batch.

### R0.7A-1 — Compatibility primitives and policy types

Add/test:

- `MediaTime` / `MediaTimeRange` value types + conversions;
- `EntityEnvelope.derived_from` defaulted lineage;
- Asset origin + usage-role value types;
- reference-analysis-only eligibility invariant;
- rights record value/seam types;
- artifact lifecycle/retention descriptor types;
- explicit legacy visual-origin restriction mapping;
- neutralize generic `MaterialProvider` after reference scan.

Do **not** migrate all persisted entities yet.

### R0.7A-2 — Domain/source-time migration

Migrate:

- Asset authoritative duration;
- Shot source range;
- ShotBoundaryProposal;
- ShotCatalog;
- frame sampling/extraction references;
- understanding requests;
- ShotIndex duration constraints;
- compatibility millisecond helpers used by existing probes.

Exit proof: R0.1/R0.2/R0.3 behavior remains equivalent while authoritative state is rational-time based.

### R0.7A-3 — SQLite schema v2 + codec compatibility

Implement:

- transactional schema v1 → v2 migrator;
- codec v1 reader + codec v2 writer;
- conservative legacy Asset role mapping;
- additive stores/seams for rights/evidence/migration metadata as required;
- reopen/restart tests;
- never silently mutate old payload JSON.

This is the highest-risk batch and should receive dedicated migration probes.

### R0.7A-4 — Derived evidence / index cleanup

Implement:

- remove new writes of ShotAnalysis embedding ownership;
- index representation provenance;
- durable-evidence vs rebuildable-cache metadata;
- cache cleanup test proving durable evidence survives.

### R0.7A-5 — Future authority contracts

Before creative implementation, add v0.2-compatible typed contracts for:

- `ResolutionDecision` + `ResolvedSelection[]`;
- `TemporalEvidence` / `TemporalAnchor`;
- `SpatialComposer` port/result;
- `MusicSelectionService` port/result;
- `AudioEditorialService` port/result;
- Review finding repair-routing fields;
- deterministic executor/trust boundary types.

These are contracts/placeholders only, not R0.9–R0.13 feature implementation.

### R0.7A-6 — Full regression / migration closure

Run and preserve evidence for:

- old SQLite project open/migrate/reopen;
- rational/VFR-style timestamp round trip;
- legacy remote/generated visual state cannot become Resolver-eligible;
- reference-analysis-only Asset rejected by eligibility gate;
- multi-selection ResolutionDecision persistence;
- cache cleanup preserves durable evidence;
- media-derived malicious text cannot become executor command;
- R0.1–R0.6 existing probes remain green or have explicit v0.2 replacements.

Then run a small private real-phone-footage Product Probe.

## 6. What should NOT happen in R0.7A

Do not add:

- DeepSeek Director quality logic;
- hybrid dense retrieval;
- ASR model dependency;
- BeatMap improvement;
- music provider integration;
- Auto Reframe algorithm;
- FFmpeg final renderer productization;
- desktop UI.

R0.7A is successful when later phases can build on truthful v0.2 contracts without compatibility debt.

## 8. First implementation recommendation

Start with **R0.7A-1 only**.

Reason:

- it establishes the value types every later migration needs;
- it is mostly additive;
- it can be validated without touching SQLite history;
- it surfaces hidden call-site assumptions before the critical persistence migration;
- it prevents old visual-source semantics from leaking into new code.

After R0.7A-1 is green, migrate source time. Only then change SQLite codec/schema.

This preserves the project's established rule:

> one coherent change → verify → commit → CI green → next batch.
