## Closure-blocking minor defects

### 1. Malformed provider scalar types are coerced instead of rejected

`providers/llm/deepseek_director.py` currently uses conversions such as `str(...)`, `int(...)` and `bool(...)` while parsing provider JSON. This can silently change malformed provider output rather than fail closed. Examples:

- `"allow_reuse": "false"` becomes Python `True` via `bool("false")`;
- floating-point `order`/`importance` values can be truncated by `int(...)`;
- non-string required text can be accepted after `str(...)` conversion;
- non-integral duration values can be truncated by `int(...)` inside `_time`.

This conflicts with the active Work Order requirement that malformed provider output fail closed.

### 2. One-sided duration bounds are silently rewritten into an exact duration

`application/use_cases/editing_director.py::_duration_constraint` maps a proposal containing only a minimum or only a maximum into `DurationConstraint(x, x)`. That changes provider intent instead of rejecting an unrepresentable open-ended bound. The current Domain `DurationConstraint` requires both bounds, so the Application seam must either receive both bounds or none.

### 3. Provider-neutral proposal DTOs do not yet enforce their own bounded contract

`application/ports/director.py::EditSlotProposal` and `DirectorProposal` have no `__post_init__` validation. Adapter-specific checks therefore are not sufficient to protect the provider-neutral seam from another future adapter returning blank required strings, ambiguous duplicate orders/slot IDs, invalid boolean/integer types, or one-sided duration bounds.
