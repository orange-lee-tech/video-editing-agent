## Result

The localized Planning/Editing coupling in `EditPlan` is closed without redesigning the downstream Editing Core.

`EditPlan` can now represent explicit Brief-rooted Editing intent without requiring ScriptPlan/ShootingPlan. Combined mode retains exact Planning references, and the pre-existing ScriptPlan+ShootingPlan shape remains intentionally compatible for legacy in-memory/test/probe construction.

Broken provenance fails closed: ShootingPlan cannot exist without ScriptPlan, and intent-free or Script-only-without-Brief shapes are rejected. Existing slot uniqueness/order guards remain intact.

## Authority invariance

Focused regression evidence proves that, for otherwise identical EditSlots/candidates/decisions:

- Planning provenance does not change Resolver output authority;
- Planning provenance does not change deterministic EDLBuilder canonical output.

No production changes were made to Resolver, CandidateWindow generation, Retrieval, EDLBuilder, Canonical EDL, Renderer, Media Understanding, subtitle, spatial, music or audio semantics. No fictitious EditPlan persistence/database migration was introduced.

## What this does not close

This closure does not claim a product-facing Editing Application workflow. The repository still needs a real Editing entry/orchestration boundary that starts from Brief/editorial intent + user footage and reuses the existing Editing Core. An empty wrapper or hand-authored EditPlan does not satisfy that downstream gate.

Final Stage-A acceptance still requires real Planning-only, Editing-only and Combined workflows through the ordinary Windows user-facing path.
