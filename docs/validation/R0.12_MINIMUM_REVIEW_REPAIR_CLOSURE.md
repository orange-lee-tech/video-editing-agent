## 2. Production ownership now exercised

The implemented route is:

```text
exact canonical EDL revision
+ RenderResult / RenderArtifact
+ audible-output intent
→ ReviewApplicationRuntime
→ RenderedMediaQc port
→ FFmpegPcmRenderedMediaQc
→ ffprobe audio-stream evidence
→ temporary PCM16 extraction
→ existing inspect_pcm16_wav evidence
→ ReviewReport + ReviewVerdict
→ PASS | CORRECTION_REQUIRED | BLOCKED
```

Authority remains separated:

```text
canonical EDL        = sole exact executable timeline authority
Renderer             = execute EDL + technical delivery verification
Review               = classify evidence + route correction
AudioEditorialService / other named owner
                     = make new editorial decisions when correction is required
Renderer/Environment = same-EDL technical rerender owner when explicitly routed
```

Review does not expose render/edit/build-EDL operations and does not write a repaired artifact.

## 6. Accepted repair semantics

### Same-EDL technical retry

Only Renderer execution / output-verification failures are eligible for `RERENDER_SAME_EDL`, and the current named bound is one retry request.

Review does not execute the retry itself.

When the bound is exhausted, the verdict becomes `BLOCKED / ESCALATE_OWNER`.

### Editorial correction

Rendered clipping or unexpected mostly-silent output with audible intent routes to `AudioEditorialService` for a fresh approved decision and therefore a new authoritative downstream revision.

Review itself does not change audio automation.

### Fail-closed conditions

Examples include:

- exact RenderArtifact / EDL revision mismatch;
- uninspectable or missing delivered output;
- contradictory RenderResult evidence;
- audible intent but no delivered audio stream;
- non-retryable EDL/media/render diagnostics;
- retry bound exhaustion.

These cannot become Review PASS by absence of evidence.

### Intentional silence

No-audio delivered output is allowed only when the request explicitly declares that audible output is not required.
