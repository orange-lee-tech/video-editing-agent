## Stage 0.5 — Driver Store / platform gate

Additional local evidence before restoration:

- machine manufacturer/model: `LENOVO 20JTS1R400` (ThinkPad T470s, type 20JT);
- BIOS: `N1WET48W (1.27)`, dated 2018-05-28;
- the physical display device was started and bound to `display.inf` / Microsoft Basic Display Adapter;
- `pnputil /enum-devices ... /drivers` reported no Intel matching driver package for the device;
- `pnputil /enum-drivers /class Display` reported only the Oray virtual-display package `oem29.inf`;
- therefore there was no signed Intel graphics package in the local Driver Store that could simply be rebound/restored.

Official-source interpretation used for the restoration decision:

- Lenovo publishes a T470s 20JS/20JT-specific Intel graphics driver path, although the OEM package is a Windows 10-era package;
- Intel publishes `31.0.101.2115` for Intel HD Graphics 520 / 6th-generation graphics and exposes a Windows 11-family download, while also marking 6th-generation graphics EOL;
- therefore the benchmark preferred the machine-specific Lenovo OEM package first and reserved the generic Intel package only as a fallback experiment.

## Stage 0.7 — FFmpeg software/D3D11VA capability probe

A deterministic 12-second 1920x1080/30 H.264 + AAC fixture was generated with the project-owned FFmpeg runtime.

Observed fixture generation:

- output: H.264 Constrained Baseline, yuv420p, 1920x1080, 30 fps;
- audio: AAC-LC, 48 kHz mono;
- generation exit code: `0`.

Observed software-decode baseline:

- 360/360 video frames decoded;
- exit code: `0`;
- approximately `20.8x` reported decode/output speed to the null sink;
- benchmark wall time approximately `0.579s`;
- max RSS approximately `64,364 KiB`.

Observed D3D11VA device initialization:

- FFmpeg explicitly selected `d3d11va adapter 0`;
- device identified as `8086:1916 (Intel(R) HD Graphics 520)`;
- initialization exit code: `0`.

Observed H.264 D3D11VA decode:

- requested hwaccel method: `d3d11va`;
- decoder reinitialized to `pix_fmt: d3d11`;
- 360/360 frames decoded;
- 0 decode errors;
- exit code: `0`;
- approximately `3.01x` reported end-to-end speed in this FFmpeg null-output probe;
- benchmark wall time approximately `3.992s`;
- max RSS approximately `173,556 KiB`.

PowerShell emitted `NativeCommandError` wrapper text because FFmpeg diagnostic output is written to stderr. This was **not** an FFmpeg process failure; the decisive process exit codes were `0` and FFmpeg reported successful completion.

### Interpretation of throughput numbers

The software-vs-D3D11VA throughput values from this probe are **not a Preview-backend performance ranking**.

This test proves device/decoder availability and fallback viability. The D3D11VA path in this command is forced through FFmpeg's null/output flow and includes synchronization / hardware-frame transfer behavior that does not model a zero-copy or direct-GPU presentation path. A real Preview backend must therefore be judged on its actual playback chain:

`decode → presentation → external seek/control → repeated seek/scrub stability`

Do not conclude from `20.8x` versus `3.01x` that software decode is generally a better interactive Preview path.
