## First preparation attempt — INVALID / NOT ACCEPTED

The first PowerShell preparation script must not be used as evidence that either candidate failed.

Observed problems were in the benchmark preparation script / HTTP handling, not in GStreamer or VLC:

1. GStreamer's `.sha256sum` response was exposed to Windows PowerShell 5.1 as `System.Byte[]`; calling `.Trim()` therefore failed and left the expected hash empty.
2. The subsequent interactive commands were still executed manually after a `throw`, so later output misleadingly printed `checksum PASS` even though the prior command had failed. The corrected procedure must be one fail-closed script unit.
3. The VLC `get.videolan.org/...zip` endpoint returned the VideoLAN download landing HTML under `Invoke-WebRequest` rather than the binary ZIP payload. The downloaded file hash therefore did not match the official ZIP checksum and `Expand-Archive` correctly rejected it.
4. The VLC `.sha256` request through the same download frontend likewise returned HTML (`<!doctype...`) rather than the raw checksum file.
5. GStreamer installation was attempted only after the invalid checksum stage and did not produce the requested private runtime. This result is not classified as a GStreamer install defect until the package is revalidated and the installer is run from a fail-closed script.

No candidate is eliminated by this attempt.

## Official-source facts for retry

### GStreamer

Current official download page reports stable `1.28.6` and recommends MSVC x86_64 when unsure. Starting with 1.28, Windows installers use Inno Setup and officially accept:

- `/DIR=path`;
- `/TYPE=runtime`;
- `/CURRENTUSER`;
- `/SILENT` / `/VERYSILENT`;
- `/NORESTART`.

The retry must save the checksum response as bytes/file and decode it explicitly rather than assuming PowerShell returns a text string.

### VLC/libVLC

VideoLAN's official 3.0.23 win64 directory contains `vlc-3.0.23-win64.zip` with expected size `79,893,405` bytes and a sidecar `vlc-3.0.23-win64.zip.sha256`.

VideoLAN's download page reports the ZIP SHA-256 as:

`992d19dbd0b8a7cde9167d2f7780b1ef6f92acc8a71acfa736101a21f35181e1`

The retry must use the static official download directory rather than treating the `get.videolan.org` landing page as a direct binary endpoint. It must verify both expected size/magic (`PK`) and SHA-256 before extraction.

## Retry acceptance gate

Candidate preparation is accepted only when the retry proves:

- package bytes are from the reviewed official distribution path;
- checksum parsing is deterministic under Windows PowerShell 5.1;
- checksum matches before any install/extract action;
- GStreamer private runtime contains `gst-launch-1.0.exe` and `gst-inspect-1.0.exe` and exposes the expected D3D11 plugin/sink surface;
- VLC private runtime contains `vlc.exe`, `libvlc.dll`, and its plugin tree;
- global `PATH` remains unchanged for candidate commands;
- failures stop the entire script rather than allowing later steps to continue and create false PASS messages.

## Interpretation

This failed preparation attempt is useful product evidence: installer/download automation itself must be diagnosable and fail closed. Stage-A/R0.14 packaging cannot assume browser-style redirects, text response types, or globally installed runtimes.
