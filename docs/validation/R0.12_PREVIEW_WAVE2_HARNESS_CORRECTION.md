# R0.12 Preview Wave 2 — Harness Correction

**Work Order:** `R0.12-PREVIEW-BACKEND-BENCHMARK-001`  
**Date:** 2026-08-16  
**Classification:** BENCHMARK_HARNESS_DEFECT; CANDIDATE RESULT UNCHANGED  

## Observed failures

The first Wave-2 explicit GStreamer proof command failed with:

- `Failed to start`
- `ERROR: pipeline doesn't want to preroll.`
- `Failed to set pipeline to PAUSED.`

The script therefore stopped before the API-level seek/scrub probes.

A second supplemental attempt explicitly naming `qtdemux`'s video pad also failed at the source-start boundary and reported the failure under:

`/GstPipeline:pipeline0/GstFileSrc:filesrc0`

with the same preroll failure pattern.

A third attempt correctly moved to the actual high-level playback stack (`playbin3`) with a canonical `file:///` URI, `d3d11h264dec` rank preference and D3D11 sink. The PowerShell wrapper stopped immediately after GStreamer wrote a normal DEBUG line to native stderr:

`DEBUG d3d11h264dec ... device support resolution 1920x1088`

No `playbin3 exit code = ...` line was reached. This is classified as a Windows PowerShell 5.1 wrapper defect, not a GStreamer playback failure: the wrapper used `$ErrorActionPreference = "Stop"` together with direct native invocation and PowerShell redirection, allowing stderr diagnostic output to be surfaced as an Error-stream record and terminate the wrapper before process exit evaluation.

The corrected `Start-Process` wrapper then produced accepted hardware-path proof:

- process exit code `0`;
- five DOT pipeline graphs;
- `GstD3D11H264Dec:d3d11h264dec0` present inside `decodebin3`;
- output caps `video/x-raw(memory:D3D11Memory), format=NV12, 1920x1080, 30/1`;
- `GstD3D11VideoSink:d3d11videosink0` present;
- device context explicitly identifies `Intel(R) HD Graphics 520`, vendor `8086`, device `1916`, `hardware=true`.

A fourth harness defect occurred before the API-control benchmark could execute. The large inline Windows PowerShell 5.1 script used boolean expressions with `-and` placed at the beginning of a continuation line, for example:

```powershell
if (
    $p.ExitCode -ne 0
    -and
    (Test-Path $stderr)
) {
```

Windows PowerShell 5.1 parsed this as an incomplete expression and aborted the entire script block before `Invoke-ControlProbe`, `$wave`, `$gst`, or `$vlc` were created. The later `CommandNotFoundException`, null `Test-Path`, detached `else`, and detached `catch` messages are cascading parse fallout, not environment or candidate failures.

## Interpretation

None of these harness failures is accepted as a GStreamer or VLC backend failure.

Wave 1 already demonstrated successful real-window playback of the deterministic fixture through both prepared private runtimes. GStreamer hardware-decoder selection is now directly proven through the actual `playbin3 -> decodebin3 -> d3d11h264dec -> D3D11Memory -> d3d11videosink` path.

The first manual pipeline was structurally brittle because MP4 demuxing exposes dynamic pads. GStreamer documentation recommends using `playbin3` / `uridecodebin3` for ordinary audio/video playback and describes `GST_PLUGIN_FEATURE_RANK` as the supported mechanism for enabling or preferring a hardware decoder. GStreamer also provides `GST_DEBUG_DUMP_DOT_DIR` specifically to inspect the internal topology created by all-in-one playback elements such as `playbin`.

The third attempt showed a separate PowerShell 5.1 native-stderr behavior. Microsoft PowerShell documentation notes that native commands commonly write informational text to stderr and that redirected native-stderr handling changed in PowerShell 7.2. This host uses Windows PowerShell 5.1.

The fourth defect is also PowerShell-version/harness syntax, not a missing product environment. Microsoft PowerShell 5.1 documentation supports implicit line continuation after a binary operator, not by placing the operator at the beginning of the next line. Therefore benchmark scripts targeting this host must keep binary operators at the end of the previous line or avoid multiline boolean expressions entirely.

## Corrective rule

- Preserve accepted Wave-1 GStreamer/VLC playback results.
- Preserve accepted GStreamer `playbin3` D3D11 hardware-path proof.
- Do not change drivers, disable Oray, reinstall runtimes, or downgrade candidates because of harness defects.
- Retire explicit `filesrc -> qtdemux -> ...` proof pipelines.
- Use actual playback stacks (`playbin3` / `GstPlay`, libVLC) for subsequent evidence.
- On Windows PowerShell 5.1, run native benchmark processes with `Start-Process -RedirectStandardOutput/-RedirectStandardError -Wait -PassThru` and classify success from process exit code plus explicit markers.
- Do not place binary operators such as `-and` at the beginning of a new line in scripts intended for Windows PowerShell 5.1. Prefer single-line boolean conditions or put the operator at the end of the previous line.
- Avoid giant interactive inline script blocks for the remaining benchmark. Generate small temporary `.py` / `.ps1` files outside the repository and execute them as files so the harness can be syntax-checked before running candidate processes.
- Use API-level pause/seek/scrub behavior as the primary control-plane hard gate.
