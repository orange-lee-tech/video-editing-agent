### VLC/libVLC 3.0.23 — first software-mode attempt

The first Wave-3 harness passed `--avcodec-hw=none` as a libVLC instance/global option. The three control sequences themselves completed successfully, but logs still showed actual D3D11VA selection:

`trying format d3d11va_vld`
`→ using hw decoder module "d3d11va"`
`→ Using D3D11VA (...) for hardware decoding`

The outer harness therefore marked those runs unresolved. That was **not** accepted as a libVLC candidate failure because the control surface was healthy and the remaining uncertainty was option propagation/configuration.

## Targeted VLC software-fallback diagnostic

A one-media targeted diagnostic then compared four paths on an already tested real HEVC phone file:

1. `vlc.exe --avcodec-hw=none`;
2. libVLC global/instance `--avcodec-hw=none`;
3. libVLC per-media `:avcodec-hw=none`;
4. libVLC global + per-media together.

Observed:

| Path | Process/control | Actual HW decoder selected | Result |
|---|---:|---:|---|
| `vlc.exe --avcodec-hw=none` | exit 0 | No | software-decode PASS |
| libVLC global option | exit 0 / CONTROL_PASS | **Yes — D3D11VA** | global option unreliable for this embedding path |
| libVLC per-media `:avcodec-hw=none` | exit 0 / CONTROL_PASS | No | software-decode PASS |
| libVLC global + per-media | exit 0 / CONTROL_PASS | No | software-decode PASS |

The per-media and combined logs explicitly show:

`looking for hw decoder module matching "none"`
`→ no hw decoder modules matched`

The global-only libVLC path instead shows:

`looking for hw decoder module matching "any"`

and proceeds to D3D11VA selection.

D3D11 video output/presentation was still present in the software-decode runs. That is not counted as hardware **decoding**.

### Accepted VLC fallback rule

For this tested libVLC 3.0.23 Windows embedding path:

- do **not** rely on the instance/global `--avcodec-hw=none` option as the sole proof of CPU decode;
- the tested per-media `:avcodec-hw=none` option is the accepted explicit software-decode control;
- a future production adapter must preserve this distinction and keep diagnostic evidence observable.

Result: **VLC/libVLC explicit software-decode fallback PASS on the tested Class-A host, with a configuration caveat.**

## Failure classification lessons

This wave reinforces the repository rule:

- harness/configuration propagation defect ≠ backend candidate failure;
- available hardware-output formats ≠ actual hardware decoder selection;
- D3D11 presentation ≠ D3D11VA decode;
- explicit decoder-selection logs are required when proving software-only decoding.

The initial libVLC global-option result is retained as useful diagnosability/integration evidence rather than erased.
