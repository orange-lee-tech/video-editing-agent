## 1. Accepted Stage-A route

The accepted automatic public-music path is:

```text
MusicDiscoveryQuery
→ Openverse audio discovery
   source = wikimedia_audio
   commercial + modification discovery filter
→ AudioMaterialCandidate
   rights remain UNKNOWN at discovery
→ current Wikimedia Commons imageinfo/extmetadata verification
→ strict Stage-A automatic rights whitelist
→ normalized LicenseSnapshot + raw source evidence Artifacts
→ one approved upload.wikimedia.org file acquisition
→ bounded project-controlled provider_audio storage
→ SHA-1 source integrity + local SHA-256 content identity
→ FFprobe media validation
→ AssetIngestService
→ PROVIDER_ACQUIRED_AUDIO + MUSIC Asset
→ existing BeatMap / MusicSelection / AudioEditorial path
```

Openverse remains discovery-only. Wikimedia current source metadata is the rights-verification authority for this adapter. Remote URLs and provider candidates never become EDL media identity or timeline authority.

## 2. Production implementation

The accepted implementation adds or closes:

- provider-neutral `AudioAcquisitionPort` with typed acquisition diagnostics;
- discovery-only `OpenverseWikimediaAudioProvider`;
- support for current Openverse Commons landing identity using `commons_pageid:<id>`;
- current-source `WikimediaAudioRightsVerifier` using MediaWiki `pageids`/`imageinfo`/`extmetadata`;
- content-addressed rights evidence through the existing ArtifactStore;
- strict CC0 / accepted Public Domain / CC BY automatic whitelist behavior;
- fail-closed NC / ND / BY-SA / NonFree / restricted / unknown behavior;
- `WikimediaAudioAcquirer` restricted to `upload.wikimedia.org:443` with public-IP DNS validation, bounded bytes/time, atomic partial commit, source SHA-1 and local SHA-256 checks;
- provider-compliant identified bot User-Agent and typed HTTP 429 / `Retry-After` evidence without automatic hammering;
- exact MIME alias comparison for only:
  - `audio/flac` ↔ `audio/x-flac`;
  - `audio/ogg` ↔ `application/ogg`;
- actual HTTP Content-Type is still preserved as evidence;
- unrelated MIME changes remain fail-closed;
- project-owned `<project>/provider_audio/` storage;
- acquired audio crosses normal `AssetIngestService` and becomes a normal authoritative local `MUSIC` Asset.

No new rights database or provider-specific timeline authority was introduced.

## 5. Live-probe governance repair

During the Engineering Probe, automatic triggering on ordinary provider-code pushes was recognized as inappropriate for an external rate-limited provider.

The accepted workflow is therefore bounded:

- ordinary deterministic CI does not call Openverse/Wikimedia;
- live provider validation is manual or explicitly marker-triggered;
- one marker update is used for a deliberate bounded run;
- concurrency does not cancel an in-flight provider run;
- HTTP 429 is surfaced as retryable evidence rather than automatically hammered;
- no bulk catalog mirroring or repeated acquisition loop is part of the accepted design.

The final acceptance used one explicit final marker update and one resulting live run.

## 6. Provider and rights limitations

PASS does **not** mean:

- every Openverse result is rights-safe;
- Openverse license metadata is final authority;
- every Wikimedia Commons item is commercially reusable;
- CC BY attribution requirements disappear;
- BY-SA / NC / ND are automatically permitted by this Stage-A policy;
- generic `application/octet-stream` is treated as equivalent to arbitrary audio MIME;
- arbitrary hosts can be downloaded;
- authenticated / cookie / browser-profile access is permitted;
- bulk Wikimedia mirroring is permitted;
- the provider catalog is guaranteed always available;
- generated-audio status is invented when the source does not provide it.

Each selected candidate must still clear current Wikimedia verification. `UNKNOWN` and `INELIGIBLE` remain blocked from automatic acquisition.

The ordinary-user local-music fallback remains valid.
