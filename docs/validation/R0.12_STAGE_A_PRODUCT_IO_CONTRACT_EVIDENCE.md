## Implementation owner audit

Observed existing boundaries supporting the contract:

- `ProjectWorkspace` already composes project-local SQLite, repositories and artifact storage under one project root;
- `AssetIngestService` only accepts an already available local file and creates immutable Asset identity from provenance, content hash and media metadata;
- `AssetUsageRole` already distinguishes `EDITABLE_VISUAL_FOOTAGE`, `REFERENCE_ANALYSIS_ONLY`, `MUSIC`, `VOICEOVER`, `SOUND_EFFECT` and other product roles;
- `ScriptPlanningWorkflow` and `ShootingPlanningWorkflow` already enforce proposal → deterministic validation/review → owner commit into persistent repositories;
- `EditingDirectorWorkflow` already treats ScriptPlan/ShootingPlan refs as optional exact-revision enrichment and supports Editing-only from Brief + local footage evidence;
- `Renderer.OutputSpec` already requires an explicit output path and `RenderArtifact` returns the final path tied to an exact EDL revision;
- the FFmpeg Renderer executes only canonical EDL against resolved local Asset media and rejects output/input path conflicts.

Therefore ordinary-user product integration can wrap existing owners rather than replacing them.

## Remote-input boundary conclusions

### Reference URL

Accepted semantic boundary:

`supported URL → acquisition adapter → controlled project-local file → normal ingest → REFERENCE_ANALYSIS_ONLY Asset → existing reference analysis/planning`

A URL never becomes direct Domain/timeline authority.

### Public music

Existing `AudioMaterialProvider` returns discovery candidates only; `AudioMaterialCandidate` explicitly is not an Asset.

Accepted missing product boundary:

`rights-aware candidate → acquisition → controlled project-local audio → ingest → MUSIC Asset + rights/provenance linkage → existing Music/BeatMap/Audio chain`

## Mixed-source-audio defect location

Current `AudioMixDecision` has one whole-EditPlan `source_audio_policy` with `PRESERVE / DUCK / MUTE`.

Current `plan_basic_mix()` chooses whole-plan PRESERVE when speech ranges exist and whole-plan MUTE otherwise.

Current `DeterministicEDLBuilder`:

- maps whole-plan PRESERVE by cloning every assembled video segment onto one SOURCE_AUDIO track;
- treats whole-plan DUCK as unsupported;
- cannot express different source-audio treatments for different grounded selections/source ranges.

This proves the P0 mixed-folder defect is an implementation-granularity issue at the Audio Editorial → grounded selection → EDLBuilder boundary, not a Renderer ownership problem.

## Next bounded implementation ownership
