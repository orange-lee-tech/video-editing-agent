## 1. Audit conclusion

The accepted Planning and Editing owner chains are real and Engineering-proven, but the current product entry remains an engineering surface rather than an ordinary Windows user surface.

The missing work is not a new Editing architecture and not a feature-rich NLE. It is one thin product layer plus one missing Planning-reference bridge.

The coherent implementation boundary is:

```text
existing accepted owner chains
+ complete reference-guidance plumbing
+ ordinary Windows launcher / presentation layer
+ product-default runtime composition
→ real Product Probe / Human Gate
```

## 2. Existing capabilities that must be reused

### Project / persistence

`ProjectWorkspace.open()` already creates or opens a project directory, initializes project SQLite, artifacts and repositories. Existing project CLI also exposes project init/status and entity show operations.

Do not create a second project format or persistence layer.

### Planning owners

Existing Script and Shooting workflows already support:

- `PlanningPolicyGuidance`;
- `ReferenceStyleGuidance`;
- semantic/commercial Review;
- persisted exact revisions.

Do not bypass these workflows from a desktop adapter.

### Reference acquisition / analysis

Accepted reference route already exists:

```text
supported direct HTTPS reference
→ DirectHttpsReferenceAcquirer
→ controlled local file
→ normal Asset ingest
→ REFERENCE_ANALYSIS_ONLY Asset
→ Shot / visual analysis
→ ReferenceStyleEvidenceService
→ ReferenceStyleGuidance
```

Reference-only Assets remain Resolver-ineligible.

Do not create a universal downloader or make reference media editable output footage.

### Editing owners

Accepted ProductFlow already reaches:

```text
local footage
→ ingest / Shot / understanding
→ Director / EditPlan
→ grounded Resolver
→ canonical EDL
→ persisted EDL
→ FFmpeg Renderer
→ Review
→ final MP4
```

Do not duplicate any of these decisions in the UI.

### Environment Doctor

Environment Doctor already reports:

- Windows / host runtime;
- FFmpeg / ffprobe;
- Preview runtime;
- DeepSeek credential readiness;
- visual-provider configuration.

Reuse this report for product diagnostics rather than inventing an unrelated checker.

## 3. Hard product gaps found

### Gap A — ordinary Planning request cannot carry the accepted reference/fact semantics

`ProductBriefInput` and `Brief` support authoritative facts and references, and DeepSeek Planning consumes both.

Current `adapters/cli/product_run.py::_brief()` does not accept either `authoritative_facts` or `references`.

Therefore a real high-performing/reference target cannot currently enter the ordinary Planning request boundary completely.

### Gap B — ProductFlow / ProjectWorkspace drop `ReferenceStyleGuidance`

`ScriptPlanningWorkflow.generate()` and `ShootingPlanningWorkflow.generate()` already accept `reference_guidance`.

However:

- `PreproductionOperations` has no reference-guidance parameter;
- `ProjectWorkspace.runtime()` wraps the workflows without forwarding reference guidance;
- `PlanningProductRequest` / `PlanningProductOperations` do not carry reference guidance;
- `build_planning_product_flow()` therefore cannot deliver accepted reference-style evidence into the real ProductFlow path.

This bridge must be repaired in the application/composition layer, not hidden inside the UI.

### Gap C — current ProductFlow requires hand-written JSON

The accepted CLI route requires:

```text
video-editing-agent run planning --request planning.json
video-editing-agent run editing --request editing.json
```

That is a valid Engineering surface but fails the ordinary-user Stage-A floor when it is the only launch path.

### Gap D — Editing exposes runtime plumbing as user-facing launch arguments

Current Engineering CLI requires the caller to know values such as:

- visual provider;
- visual model;
- TransNetV2 model weights path;
- device;
- ffmpeg / ffprobe paths;
- output dimensions / fps.

Those are composition/runtime configuration, not editorial meaning.

The ordinary-user product path must choose reviewed defaults, auto-resolve available runtime where safe, and surface an understandable diagnostic when a capability is unavailable.

In particular, users must not be required to locate a TransNet `.pth` file manually.

### Gap E — no ordinary Windows launcher / file chooser exists

`src/video_editing_agent/adapters/` currently contains only CLI adapters. No existing Tk/PySide/PyQt/desktop launcher was found.

The ordinary product needs a minimal Windows-facing shell for:

- project directory create/open;
- Planning inputs and production constraints;
- reference URL/local reference selection;
- Editing file/folder selection;
- output destination;
- run/start control;
- progress/failure visibility;
- result discovery.

A timeline editor, preview editor or feature-rich NLE is not required.

### Gap F — Planning result is not directly inspectable from ProductFlow result

Current `planning_result_json()` returns exact refs and progress events but not readable ScriptPlan/ShootingPlan content.

The user can technically recover entities through lower-level `show` commands, but that is not an ordinary Product Gate experience.

The product shell must load the exact returned revisions and present/export readable ScriptPlan and ShootingPlan content.

### Gap G — progress events exist but are only visible after completion

ProductFlow has ordered `ProductFlowEvent` stages, but the current CLI returns them only in the terminal JSON after synchronous completion.

The ordinary-user shell should display those same application-owned stages as work proceeds. It must not invent a second progress authority.

### Gap H — folder convenience is missing from the current Editing request surface

Current Editing request expects a non-empty explicit file list.

The Stage-A Product I/O contract allows a folder as a product convenience that deterministically expands to files. The ordinary Windows shell should provide file and folder selection without introducing a Domain Folder entity.

## 4. Frozen implementation direction

### 4.1 Application/reference bridge

Add one product-facing reference input DTO that represents user meaning without internal Asset/Shot IDs, for example:

```text
PlanningReferenceInput
- kind / purpose
- direct HTTPS URL OR local file
```

The product composition layer should:

1. acquire/copy/select reference into controlled local media where required;
2. ingest it as `REFERENCE_ANALYSIS_ONLY`;
3. run exact Shot detection and visual understanding using accepted adapters;
4. build `ReferenceStyleEvidence`;
5. convert it to existing `ReferenceStyleGuidance`;
6. persist/attach the exact reference Asset revision to the Brief reference metadata;
7. forward the guidance into both Script and Shooting workflows.

No URL/provider content becomes timeline or Resolver authority.

### 4.2 Preserve raw ProductFlow API as reusable application surface

Extend the accepted ProductFlow rather than creating a separate UI-only orchestration path.

Required properties:

- Planning without references still requires only DeepSeek Planning capabilities;
- reference analysis capabilities are required only when a reference input is actually supplied;
- Editing remains independently activatable;
- Combined remains optional exact Planning enrichment;
- existing tests/callers remain compatible where practical.

### 4.3 Live progress sink

Reuse `ProductFlowEvent` and add a small optional event callback/sink at the application boundary so adapters can observe events as they occur.

The sink is observation-only and must not acquire decision authority.

### 4.4 Minimum Windows launcher

Preferred first implementation: a stdlib Tkinter desktop adapter **only if the actual Windows development/runtime environment verifies Tk availability**.

Do not add a large GUI framework merely for Stage-A. If Tk is unavailable on the real target environment, stop and report that concrete blocker before adding a new dependency.

The launcher should be intentionally plain and contain two primary modes:

#### Planning

- choose/create project directory;
- goal/title/objective/audience/platform/core message;
- optional authoritative facts;
- optional direct HTTPS or local reference media;
- production constraints/resources;
- Run Planning;
- live progress;
- readable ScriptPlan;
- readable ShootingPlan;
- clear failure text.

#### Editing

- choose/create project directory;
- choose files and/or folder;
- editing intent / Brief fields;
- choose final MP4 path;
- optional use of Planning output from the same project without typing revision IDs where the launcher can resolve the intended exact revision safely;
- Run Editing;
- live progress;
- Review/correction result;
- final output path with an ordinary reveal/open-folder action where safely supported.

### 4.5 Product runtime defaults

The launcher/composition should hide normal provider plumbing:

- DeepSeek model: reviewed project default unless advanced configuration is explicitly needed;
- visual provider/model: reviewed project default based on configured credential;
- TransNetV2: auto-resolve reviewed installed runtime/weights rather than requesting a path from the user;
- FFmpeg/ffprobe: normal executable discovery plus existing Doctor diagnostics;
- CPU is a valid compatibility baseline; hardware acceleration is optional.

Do not silently switch semantic providers on an execution failure. Missing capability should produce a typed, understandable diagnostic.

### 4.6 Environment Doctor gap

If necessary for ordinary Editing diagnostics, extend Environment Doctor with the minimum mandatory Shot-detection/runtime readiness check required by the product shell.

Do not turn Doctor into an installer or creative-state mutator.

## 5. Required deterministic tests

At minimum cover:

1. raw Planning reference input does not require AssetRef/ShotRef;
2. direct URL acquisition stays reference-analysis-only and Resolver-ineligible;
3. local reference input also stays reference-analysis-only;
4. reference-style guidance reaches Script Planning;
5. the same guidance reaches Shooting Planning;
6. Planning without references remains valid;
7. authoritative facts/references survive ProductFlow Brief commit;
8. event sink observes the same ordered ProductFlow events without changing results;
9. folder expansion is deterministic and does not mutate originals;
10. default runtime resolution never requires the ordinary user to supply a TransNet weight path;
11. unavailable mandatory runtime produces understandable diagnostics;
12. launcher/controller can build Planning requests without hand-written JSON;
13. launcher/controller can build Editing requests from selected files/folder and output path;
14. Planning presentation loads the exact returned ScriptPlan/ShootingPlan revisions;
15. Editing presentation exposes final MP4 / Review correction state;
16. Planning-only, Editing-only and Combined semantics remain green;
17. all existing architecture contracts and repository Quality Gate remain green.

UI widget layout itself should not carry business logic; keep most behavior testable below the Tk widget layer.
