## Scope accepted

This closure accepts the bounded Stage-A structured subtitle execution path:

`StructuredSubtitleCue → canonical EDL subtitle payload → deterministic ASS artifact → FFmpeg/libass → rendered MP4`.

The closure does not expand the product into a general typography, karaoke or multilayer subtitle system.

## Independent audit result

The original implementation candidate `12e4049c53a9597fba2a6654701d779d496b9433` was held because:

1. exact rational cue boundaries were silently rounded to ASS centiseconds;
2. multiple canonical SUBTITLE tracks/layers were flattened to ASS Layer 0;
3. live evidence did not yet exercise comma/apostrophe punctuation in the actual ASS filter path.

The final closure commit resolves those guards without redesigning the subtitle model:

- non-centisecond boundaries are detected and rejected with `SUBTITLE_TIMING_UNREPRESENTABLE` before FFmpeg invocation;
- multiple subtitle tracks or any nonzero subtitle layer are rejected with `SUBTITLE_LAYER_UNSUPPORTED` before invocation;
- ASS timestamp formatting itself also refuses non-centisecond values rather than silently rounding;
- the live probe places the ASS artifact beneath a controlled parent directory containing both comma and apostrophe punctuation and completes real libass rendering.

Canonical EDL therefore remains the sole exact executable timeline authority. Renderer encodes only semantics the Stage-A backend can faithfully represent and fails closed otherwise.

- Rich typography/karaoke/multilayer subtitle composition remains out of scope.
- The multilingual probe proves controlled rendered-region changes, not universal semantic glyph correctness under arbitrary installed fonts.
