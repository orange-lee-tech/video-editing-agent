## 4. Deterministic capability semantics

### Host runtime

The Stage-A ordinary-user runtime currently classifies Windows + Python 3.12+ as READY.

A non-Windows host is reported honestly rather than crashing. An older Python on Windows is represented as installation-required instead of being mistaken for a supported runtime.

CPU/GPU identity is not a basic-product readiness gate.

### FFmpeg / ffprobe

Readiness requires:

```text
resolve executable
→ execute bounded `-version` process with `shell=False`
→ successful return code
→ normalized version evidence
```

Executable presence alone cannot produce READY.

Missing tools become `AVAILABLE_AFTER_INSTALL`; a resolvable executable whose bounded probe fails becomes `UNAVAILABLE`.

### Preview

If no approved private GStreamer runtime is configured for Doctor, Preview is reported as `AVAILABLE_AFTER_INSTALL`.

If a backend is supplied, the Doctor calls the production `PreviewBackend.initialize()` contract and classifies the resulting typed `PreviewStatus`; it does not inspect a directory and assume success, and it does not switch backend families.

The already accepted production GStreamer Preview Windows evidence remains authoritative for the actual bundled/private runtime behavior; this Work Order intentionally did not download that large runtime again solely to decorate Environment Doctor evidence.

### Cloud provider configuration

Current product-path configuration checks include:

- `DEEPSEEK_API_KEY` for Planning and Editing Director configuration;
- `GEMINI_API_KEY` or `OPENAI_API_KEY` as supported visual-understanding alternatives.

Credential **presence** is configuration evidence only. It is not a live provider-connectivity PASS.

The check/report surface never stores or prints the credential value.

## 5. Secret and execution boundary

Environment Doctor evidence intentionally avoids:

- API-key values;
- OAuth tokens/cookies;
- full environment dumps;
- raw tool stderr in the ordinary repair report;
- unrelated personal paths;
- media-derived text;
- model-generated repair shell commands.

FFmpeg probes use direct argument-array subprocess execution with `shell=False` and a bounded timeout.

Repair guidance is declarative. This Work Order does not auto-install dependencies or execute generated repair instructions.
