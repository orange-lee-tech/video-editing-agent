## Why 0.1.2 exists

The 0.1.1 Human Gate proved installed Planning worked and Editing reached real Gemini visual understanding. Multiple visual calls succeeded before a later request returned retryable HTTP 503 with provider text indicating temporary high demand.

The adapter already classified HTTP 5xx as `VisualProviderTransientError` and the production composition already wrapped visual understanding with a retry decorator. However, the previous default was only 3 attempts with local delays of 0.3 and 0.6 seconds when the provider supplied no RetryInfo. That was insufficient resilience for a realistic temporary demand spike.

0.1.2 changes only this bounded transient-provider policy and advances release identity so the published 0.1.1 binary remains immutable.

## Retry policy evidence

Default visual transient policy is now:

- maximum attempts: 5;
- local exponential delays: 2 / 4 / 8 / 16 seconds;
- provider RetryInfo remains authoritative when it requests a longer wait;
- non-transient response/schema failures are not retried;
- exhausted retry budget preserves `VisualProviderTransientError` and original provider context;
- final error states that the automatic retry budget was exhausted.

Automated tests cover successful recovery on the fifth attempt, provider RetryInfo precedence, non-retryable error behavior, exhausted-budget typing/context and policy validation.
