Status: **CLOSED — validated on 2026-08-10**

## Scope

R0.2 closes the identity bridge between real local media and authoritative `Shot` objects:

`local file -> ffprobe -> AssetIngestService -> Asset -> ShotDetector -> ShotBoundaryProposal[] -> ShotCatalog -> Shot[]`

The phase does not perform semantic footage understanding. `Shot` identity remains boundary-based and
semantic analysis remains a separate derived revision owned by `UnderstandingService`.

## R0.2-A — Asset and Shot identity foundation

Implemented:

- `AssetProvenance` and the reviewed Asset v0.1.1 fields;
- local `MediaSource` input;
- streaming SHA-256 content hashing;
- canonical local file URI registration;
- injected `MediaProbe` seam;
- authoritative `ShotCatalog.commit_boundaries()`;
- `sht_*` identity creation and previous/next neighbor references;
- strict same-Asset, contiguous and non-overlapping boundary validation.

## R0.2-B — real ffprobe metadata

Implemented a provider-independent `MediaProbe` contract and an FFmpeg `ffprobe` adapter. The real
Windows integration probe generated an audiovisual MP4 and produced:

```text
media_kind=video
```

The same ingest created a canonical `sha256:` content hash.

## R0.2-C — real Asset to committed Shots

A four-second synthetic hard-cut MP4 was passed through the complete identity chain on Windows Server
2025 with the pinned FFmpeg 8.1 build and the validated `transnetv2-pytorch==1.0.5` runtime.

Final observed result:

```text
Asset-to-Shots pipeline probe: PASS
asset_ref=ast_pipeline_probe@1
asset_duration_ms=4000
proposal_count=4
```

The committed Shots cover the complete Asset duration, preserve the exact Asset revision, contain no
gaps or overlaps, and have consistent forward/backward neighbor references.

## Integration bug found by R0.2-C

The first full-chain probe exposed a semantic mismatch that unit-isolated modules had not revealed.
The TransNetV2 backend already emitted **internal cut boundary timestamps**, but the detector core fed
those values into an older helper designed for a list of scene-end timestamps that includes the media
end. That helper intentionally dropped its final input, so the valid final internal boundary was lost.

For the known probe boundaries `(960, 1960, 2960)` this produced only three Shots instead of four.

The fix makes the internal capability contract explicit:

`model output -> boundary_times_ms -> duration policy -> source ranges`

`total_duration_ms` is now the sole media-end authority. The normalized backend never represents media
end as an internal boundary. A dedicated regression test requires the three internal boundaries above
to produce four proposals.

## Next phase

R0.3 begins footage understanding. The next implementation boundary is intentionally provider-neutral:

1. derived `ShotAnalysis` contract and `AnalysisProfile`;
2. deterministic frame-sampling plan from immutable Shot source ranges;
3. media sample extraction / artifact handling;
4. only then vision/speech/model provider adapters.

No understanding component may change `Shot` identity or source boundaries.
