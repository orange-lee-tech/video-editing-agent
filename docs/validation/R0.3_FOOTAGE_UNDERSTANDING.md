## R0.3-D — UnderstandingService revision ownership

Implemented the provider-neutral visual UnderstandingService owner with explicit repository and media
resolution ports. Its data flow is:

`ShotRef -> ShotRepository -> AssetMediaResolver -> sampling -> real frame extractor -> ArtifactStore -> VisualUnderstandingPort -> VisualSemanticsProposal -> deterministic normalization -> ShotAnalysis revision -> ShotAnalysisRepository`

The visual implementation currently supports `semantic`, `deep_visual` and `editorial`. `speech` and
`basic` are deliberately not faked; unsupported profiles fail explicitly until their own capabilities
exist.

The real Windows ownership probe at commit `fe62e09c812a552d0fc7388a511a9b5c8ee0dfe8` used a real
two-second video, real FFmpeg PNG extraction and a real local ArtifactStore. Only the visual model was

## R0.3-E — FireRed-informed provider hardening

Reviewed FireRed `understand_clips` and its detail/overall prompts at fixed revision
`c9e945215586f45c12a61c1951ee9a8e9c43a027`. No FireRed source or prompt text was copied.

The useful ideas retained are grounded subject/action/environment/framing description, normalized
visual-quality evaluation, per-item failure isolation, and bounded retry of transient provider errors.
They were translated into local typed contracts rather than FireRed dictionaries:

- `VisualQualityScoreProposal` requires a finite `[0, 1]` value;
- accepted visual quality commits as derived `NamedQualityScore` only after validation;
- provider failures use `VisualProviderTransientError` / `VisualProviderResponseError`;
- `RetryingVisualUnderstandingPort` retries only explicit transient failures using bounded linear
  backoff;
- malformed responses do not retry and never become fake captions;
- sentinel values such as `aes_score=-1` are forbidden;
- collection-wide summarization remains outside `ShotAnalysis` ownership.

At `db1fff9d3afc231832dbdb12b267edbcae0395e5`, the main quality gate passed.
See `docs/upstream/FIRERED_UNDERSTAND_CLIPS_R0.3.md` for the selective-audit record.

## R0.3 closure statement

The provider-neutral footage-understanding foundation now proves:

1. immutable Shot revisions deterministically select source-frame timestamps;
2. real FFmpeg extraction produces traceable PNG samples;
3. frame payloads receive durable content-addressed Artifact identity;
4. a provider receives only a typed request and returns only a Proposal;
5. semantic text and visual-quality values are deterministically normalized;
6. transient provider errors can be retried without converting failures into semantic data;
7. only `UnderstandingService` creates or increments `ShotAnalysis` revisions.

A concrete visual model is intentionally **not** part of this closure. Before real model calls are
introduced, Asset / Shot / ShotAnalysis records must survive process restart through a minimal local
persistence layer.

## Next phase

R0.4 establishes local structured persistence for revisioned records. Binary artifacts remain in the
content-addressed ArtifactStore. SQLite is the candidate implementation and must be recorded through an
ADR before repository code depends on it.
