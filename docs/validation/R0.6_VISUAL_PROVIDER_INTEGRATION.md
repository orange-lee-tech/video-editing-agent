# R0.6 Visual Provider Integration — Validation Record

Status: **CLOSED — 2026-08-10**

## Objective

R0.6 validates the first concrete `VisualUnderstandingPort` provider without transferring semantic
ownership away from `UnderstandingService`.

The provider is allowed to convert sampled frame artifacts into a `VisualSemanticsProposal`. It is not
allowed to create or revise `ShotAnalysis`, write editing decisions, own Shot identity, or mutate
`ShotIndex` directly.

## R0.6-A — optional provider adapter seam

The first concrete adapter established the provider implementation pattern behind the existing
`VisualUnderstandingPort` while preserving the proposal-only boundary.

The OpenAI Responses implementation remains available as an optional provider. It introduced no SDK
dependency and did not change Domain or Application ownership.

## R0.6-B/C — Gemini cost-efficient visual provider

The default cost-efficient visual path was implemented with Gemini using the same provider-neutral port.

The Gemini adapter:

- uses Python stdlib HTTP rather than a provider SDK;
- reads sampled frame bytes only through `ArtifactStore`;
- sends ordered frame timestamps plus inline image payloads;
- requests structured JSON matching the existing visual-proposal shape;
- returns only `VisualSemanticsProposal`;
- maps retryable HTTP failures to `VisualProviderTransientError`;
- maps provider/schema failures to `VisualProviderResponseError`;
- adds no new Python runtime dependency.

The accepted live model is:

`gemini-3.5-flash-lite`

A first attempt tried to infer a stable Flash-Lite model from `models.list`. Real API evidence showed that
this metadata assumption was not reliable for the account response, so dynamic discovery was removed.
The live path now pins the documented stable model explicitly rather than guessing from provider metadata.

The current Gemini generation request also avoids deprecated sampling parameters.

## Boundaries preserved

R0.6 does **not** grant any visual provider authority to:

- revise `Shot` identity or boundaries;
- commit `ShotAnalysis` directly;
- choose an EditSlot or source window;
- create `ResolutionDecision`;
- modify EDL or timeline state;
- become a Domain dependency.

Gemini and OpenAI remain replaceable provider adapters.

## Cost policy

The default live visual provider is the stable Flash-Lite tier because visual understanding is a
high-frequency factual extraction task. Higher-cost providers/models may be introduced only as optional
fallbacks or quality-review tiers behind the same port.

Local deterministic stages such as FFmpeg, TransNetV2, metadata extraction, persistence and lexical
retrieval remain preferred before paid/cloud inference.
