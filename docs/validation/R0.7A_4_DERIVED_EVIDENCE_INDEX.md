## Scope

R0.7A-4 separated four concerns that had previously been easy to conflate:

```text
Shot semantic understanding
!= retrieval representation/model state
!= binary content identity
!= artifact lifecycle/retention policy
```

Implemented:

- removed `ShotAnalysis.embedding_ref` from current semantic state;
- codec readers tolerate historical payloads containing `embedding_ref`, but current codec v2 writes no embedding ownership field;
- introduced `ShotIndexRepresentationDescriptor` for rebuildable representation/model/revision/dimension/normalization provenance;
- retained content-addressed artifact identity in `ArtifactStore` / `LocalArtifactStore`;
- introduced persistent artifact lifecycle metadata beside, but independent from, binary content identity;
- lifecycle metadata supports multiple references to the same binary with different retention classes;
- added `ArtifactCleanupService` with fail-closed cleanup policy;
- a binary may be deleted as cache only if **all known lifecycle references** are rebuildable-cache references;
- no lifecycle metadata means cleanup refuses deletion;
- durable derived evidence and project-output references dominate cache references.

No dense retrieval model, vector database, embedding runtime or external dependency was introduced.

## Product/architecture evidence

Dedicated tests prove:

- lifecycle metadata survives repository reopen;
- the same content-addressed binary referenced as both cache and durable evidence is not deleted;
