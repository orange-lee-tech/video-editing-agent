## Closure scope

R0.7A-6 verifies that the Architecture v0.2 migration foundation can be carried forward without silently reintroducing historical millisecond authority or bypassing the ownership seams established in R0.7A-1 through R0.7A-5.

The closure audit found one meaningful R0.1 compatibility debt before phase closure: the historical TransNetV2 backend still represented resolved media duration and scene-boundary output as integer milliseconds. Although Domain Asset/Shot/Sampling had already migrated to canonical rational `MediaTime`, that backend seam could force a real source with a duration such as `2.5025s` back through `duration_ms`.

This was not accepted as a known issue for R0.7B.

## Exact-time Shot Detection closure

A v0.2 exact-time seam now exists at:

```text
src/video_editing_agent/media/shot_detection/v02_exact.py
```

The active v0.2 path is conceptually:

```text
Asset.duration: MediaTime
→ ExactResolvedVideoAsset
→ ExactTransNetV2SceneBoundaryBackend
→ frame-index-derived MediaTime boundaries
→ exact rational duration policy
→ ShotBoundaryProposal(source_range: MediaTimeRange)
→ ShotCatalog
→ Shot(source_range: MediaTimeRange)
```

The historical R0.1 millisecond backend remains available as compatibility/history. It is not the new v0.2 authority path.

## Exact-time regression tests

`tests/unit/test_v02_exact_shot_detection.py` proves:

- a `1001/400s = 2.5025s` source duration survives Detector → Proposal → ShotCatalog without integer-millisecond conversion;
- a `1/24s` source cut remains exactly `1/24s`;
- attempting to use the legacy millisecond adapter for that non-millisecond cut raises instead of rounding;
- max-duration policy can partition a `1001/400s` source into three exact `1001/1200s` ranges;
- exact ranges remain contiguous and close exactly at the authoritative source duration;
- malformed unsorted/duplicate exact boundaries fail validation.

The first test commit exposed only a test-harness error (`zip(..., strict=True)` on intentionally unequal iterables). The implementation itself did not fail the exact-time assertions. The assertion was corrected without changing implementation semantics.

## Private real-phone-footage Product Probe

A user-owned local phone-video sample was tested on Windows. The private media itself was not uploaded or committed.

The final composite had:

```text
asset_duration=26766667/1000000s
asset_duration_decimal=26.766667s
proposal_count=3
shot_count=3
shot_ranges=[
  0/1s      → 178/25s,
  178/25s   → 429/25s,
  429/25s   → 26766667/1000000s
]
```

Decimal cut positions were therefore:

```text
cut 1 = 7.120 s
cut 2 = 17.160 s
```

The user independently retained three source clips corresponding visually to the composite's three shots. Their local `ffprobe` durations were:

```text
clip 1-1 = 9.566667 s
clip 1-2 = 10.091250 s
clip 1-3 = 7.211083 s
composite = 26.766667 s
```

Manual visual inspection confirmed the composite order and detected Shot identity mapping as:

```text
Shot 1 ≈ clip 1-3
Shot 2 ≈ clip 1-2
Shot 3 ≈ clip 1-1
```

Using the independently probed clip durations as a practical reference, cumulative reference boundaries are approximately:

```text
reference boundary 1 = 7.211083 s
reference boundary 2 = 17.302333 s
```

Compared with the detected boundaries:

```text
cut 1 delta ≈ -0.091083 s  (~91 ms early)
cut 2 delta ≈ -0.142333 s  (~142 ms early)
```

This is accepted for this phase, but only with an explicit quality guard.

## Boundary-quality guard

The Product Probe established an important product-quality constraint:

> Correct Shot count is not sufficient evidence of acceptable Shot Detection quality.

For this sample, the observed boundary displacement of roughly `91–142 ms` is considered **barely acceptable** by the user and must not be treated as generous error budget for future regressions.

Therefore later Shot Detection / Temporal Evidence benchmarking must:

1. score boundary accuracy separately from Shot-count accuracy;
2. preserve exact rational source time and never hide error through millisecond rounding;
3. use human-annotated acceptable cut ranges on the final tested asset timeline;
4. flag materially larger boundary displacement for regression review, threshold calibration or provider escalation;
5. avoid freezing `142 ms` as a universal product threshold from a one-video sample.

The last point matters because the independently probed source-clip durations sum to `26.869000 s`, while the final composite is `26.766667 s`. Re-encoding/concatenation therefore changed total timing by about `102 ms`. The `91–142 ms` values are strong practical evidence, but they are not laboratory-grade frame annotations of the final composite.

A later benchmark corpus should annotate the final media itself and define acceptable cut ranges rather than infer exact truth only from source-file durations.
