## Why faster-whisper remains the baseline

The R0.8 baseline needs:

- Windows-capable local inference;
- CPU-only operation without a high-end GPU;
- segment and word timestamps;
- multilingual support;
- deterministic provenance/pinning hooks;
- a Python integration path that does not import a second timeline/domain model;
- a replaceable provider seam.

The Windows Engineering Probe demonstrated those required properties without evidence that switching to `small` or `whisper.cpp` is currently justified.

`whisper.cpp` remains a benchmark/reference candidate if future product evidence shows that CPU latency, deployment footprint, or accuracy materially requires comparison.

## Authority / timestamp boundary

The upstream runtime is never source-time authority.

The adapter contract remains:

1. receive the exact local media path plus authoritative Shot `source_range`;
2. ask upstream to process only that source interval;
3. request word timestamps;
4. keep upstream internal VAD disabled for the ASR evidence pass;
5. convert provider timestamps into Shot-relative proposals;
6. return only a `SpeechRecognitionProposal`;
7. let the local owner validate every range and map it back to original Asset rational time before persistence.

No provider output writes `SpeechTranscript` directly.

## VAD separation

`vad_filter=False` remains mandatory for this ASR path.

VAD/silence is independent TemporalEvidence so later phrase/time mapping can combine:

```text
ASR words/segments
+
voice activity / silence
+
phrase/sentence structure
```

without hiding segmentation policy inside ASR.

## Offline behavior

After explicit cache preparation, a fresh-process probe succeeded with:

```text
local_files_only=True
HF_HUB_OFFLINE=1
HTTP/HTTPS proxy forced to an unreachable local endpoint
```

The model loaded and transcribed without network fallback.

Normal application runtime must therefore retain explicit model acquisition and `local_files_only=True` behavior.

## Owner / persistence evidence

Repository regressions verify:

- provider source/clip timestamps become Shot-relative proposals;
- the owner maps proposals onto original Asset rational time;
- words/segments cannot exceed the exact Shot;
- invalid or out-of-order proposals commit nothing;
- transcript revisions persist and reload through SQLite;
- `vad_filter=False` remains asserted.

The live provider produced real segment and word timing. The live provider and deterministic owner/persistence chain have been verified separately. A reusable provider → owner → SQLite reopen probe remains desirable as an integration regression, but its absence is not treated as evidence that the already-tested authority boundary failed.
