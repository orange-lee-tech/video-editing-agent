## Why faster-whisper first

The R0.8 baseline needs:

- Windows-capable local inference;
- CPU-only operation without a high-end GPU;
- segment and word timestamps;
- multilingual support including Chinese/Japanese/Korean;
- deterministic provenance/pinning hooks;
- a Python integration path that does not import a second timeline/domain model;
- a replaceable provider seam.

`faster-whisper` exposes word timestamps, CPU INT8 execution, explicit model revision loading, and `local_files_only` behavior. Its Python integration is smaller for this repository than owning a C/C++ build/binding chain in the first baseline.

`whisper.cpp` remains a strong benchmark/reference candidate, particularly for CPU efficiency and portable binary deployment. It is not rejected. The first baseline simply avoids adding native build/binding ownership before benchmark evidence shows that complexity is justified.

## Authority / timestamp boundary

The upstream runtime is never source-time authority.

The prototype adapter must:

1. receive the exact local media path plus authoritative Shot `source_range`;
2. ask upstream to process only that clip;
3. request word timestamps;
4. keep upstream internal VAD disabled for the ASR evidence pass;
5. convert returned clip/source timestamps into **Shot-relative proposals**;
6. return only a `SpeechRecognitionProposal`;
7. let the local owner validate every range against the exact Shot and map it back to original Asset rational time before persistence.

No provider output writes `SpeechTranscript` directly.

## VAD separation

Although faster-whisper v1.2.1 contains Silero VAD V6 support, `vad_filter=True` is not the R0.8 evidence architecture.

VAD/silence must be emitted as independent local temporal evidence so later phrase/time mapping and Resolver candidate construction can reason over:

```text
ASR words/segments
+
voice activity / silence
+
semantic phrase structure
```

rather than treating VAD as an invisible ASR preprocessing detail.

The adapter therefore keeps `vad_filter=False`. A separate VAD provider/service will own speech/silence evidence.

## Model / distribution guard

Normal application runtime defaults to `local_files_only=True`.

This prevents the ASR adapter from turning recognition into a hidden network operation. Model acquisition will be an explicit installation/cache-management concern with recorded revision/hash/provenance.

The prototype model repository is about 148 MB and advertises 99-language multilingual support. Model file hash and actual installed disk footprint will be recorded by the runtime Engineering Probe rather than guessed here.

## Benchmark gate still open

Before changing this entry to `DIRECT-APPROVED`, collect at least:

- Windows x86-64 install success under Python 3.12;
- actual resolved dependency versions;
- exact cached model file hashes;
- CPU model-load time;
- CPU transcription wall time / real-time factor on a short speech fixture;
- peak/representative memory observation if practical;
- segment/word timestamp presence;
- exact Shot clip → local proposal → original Asset time mapping evidence;
- no hidden network use when `local_files_only=True` after cache preparation;
- multilingual sanity evidence, preferably including Chinese;
- comparison signal sufficient to decide whether `base` is adequate or `small`/whisper.cpp deserves escalation.

No Product Probe is needed to decide whether the runtime installs and maps timestamps correctly. Product evidence comes later on private real footage after Engineering Probe success.
