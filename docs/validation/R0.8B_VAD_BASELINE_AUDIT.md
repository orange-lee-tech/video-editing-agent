## Why ONNX-only remains the baseline

The reviewed `silero-vad` Python package introduces mandatory Torch/Torchaudio dependencies even when ONNX is desired.

R0.8 only needs a small CPU-capable local VAD evidence path:

```text
FFmpeg
→ 16 kHz mono PCM
→ NumPy
→ ONNX Runtime CPU
→ pinned Silero ONNX model
```

The Windows Engineering Probe showed that this path works without adding a second deep-learning framework stack solely for VAD.

## Evidence semantics

The provider does not write Domain evidence directly.

It returns a complete Shot-relative `VoiceActivityProposal`. The local owner validates that the partition:

- begins at exactly Shot-relative zero;
- contains no gap;
- contains no overlap;
- alternates speech/silence states after adjacent same-state merging;
- ends at the authoritative exact Shot duration;
- carries finite confidence for the stated class.

Only after validation does the owner map ranges to original Asset rational time and atomically persist the full evidence batch.

## Probability and confidence rule

The approved first baseline remains intentionally transparent:

```text
p = Silero speech probability

if p >= 0.5:
    class = speech
    class_confidence = p
else:
    class = silence
    class_confidence = 1 - p
```

Adjacent equal classes are merged. Their confidence is the valid-sample-weighted mean of the per-window class confidence.

Hysteresis, minimum speech/silence duration, padding, or other segmentation policy requires benchmark evidence and a changed `provider_revision`; it must not silently overwrite evidence from this producer version.

## Atomic partition persistence

Voice activity is one complete speech/silence partition, so its evidence rows are persisted in one SQLite transaction.

If one immutable record conflicts, the whole batch rolls back. A half-written VAD result must never become observable as if missing spans meant factual silence/speech absence.

For the same exact Shot plus `provider_id + provider_revision`, a changed partition remains a nondeterminism error.

## Audio decoding

The baseline retains the provider-internal FFmpeg decoder:

- exact requested Shot source interval only;
- mono;
- 16 kHz;
- signed 16-bit little-endian PCM;
- streamed in 512-sample windows;
- final partial window zero-padded for inference only;
- no whole-clip raw-audio buffering.

No decodable audio is not converted into fake silence. It produces an unavailable/error result.

## ONNX Runtime version plan deviation

The original prototype audit required a comparison between a known-working 1.28.x release and ONNX Runtime 1.29.0 before exact runtime approval.

Observed reality on 2026-08-13:

- ONNX Runtime v1.29.0 is a real upstream release published on 2026-08-12 and includes Windows x64 release artifacts;
- the Engineering Probe could not install Python `onnxruntime==1.29.0` from its configured package index or explicit PyPI path;
- therefore no Python-runtime comparison was technically possible in the target environment;
- ONNX Runtime 1.28.0 installed and executed the pinned Silero model correctly with strong CPU margin.

The same-day 1.29.0 comparison is therefore **deferred, not passed**.

It is no longer a blocking R0.8 baseline gate because there is no evidence that 1.29.0 is required to fix a current mechanism defect, while 1.28.0 is directly verified on the target environment.

Re-open the comparison when a compatible Python 3.12 Windows x64 wheel is actually available through the approved acquisition path, or when a concrete 1.28.0 defect justifies escalation.

Do not silently upgrade to 1.29.0 merely because it is newer.
