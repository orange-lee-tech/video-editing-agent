# R0.8B VAD Prototype Baseline Audit

**Status:** PROTOTYPE BASELINE — not DIRECT-APPROVED  
**Date:** 2026-08-12  
**Capability seam:** `VoiceActivityPort`  
**Architecture owner:** local `ProviderNeutralVoiceActivityService`

## Decision

Use a lightweight ONNX-only Silero VAD prototype without depending on the upstream `silero-vad` Python package:

```text
upstream: snakers4/silero-vad v6.2.1
upstream commit: 7e30209a3e901f9842f81b225f3e93d8199902b1
model path in upstream: src/silero_vad/data/silero_vad.onnx
model Git blob SHA: 80c5592ef1f4c9ede3e357bbd02eb863358a6a9d
model size observed in upstream: ~2.33 MB
sample rate: 16000 Hz
window size: 512 samples (~32 ms)
execution provider: CPU
```

The exact ONNX Runtime package version remains an Engineering Probe variable. The adapter records the actual runtime version in `provider_revision` and accepts only ONNX Runtime major version 1.

## Why not depend on the silero-vad Python package

The reviewed v6.2.1 package declares mandatory `torch` and `torchaudio` dependencies even when ONNX is the desired execution backend.

R0.8 needs a small CPU-capable local VAD evidence path, not a second deep-learning framework stack. The prototype therefore uses:

```text
FFmpeg
→ 16 kHz mono PCM
→ NumPy
→ ONNX Runtime CPU
→ pinned Silero ONNX model
```

This keeps the dependency surface materially smaller and avoids adding PyTorch solely for VAD.

## Upstream call contract retained

The upstream ONNX wrapper for 16 kHz audio uses:

- 512 current samples per model call;
- 64 samples of retained context;
- recurrent state shape `(2, batch, 128)`;
- ONNX inputs `input`, `state`, and integer `sr`;
- model output as a speech probability plus updated state.

The local prototype follows that inference contract but owns its own provider/domain boundary and does not import upstream Domain semantics.

## Evidence semantics

VAD does not write Domain evidence directly.

The concrete adapter returns a complete Shot-relative `VoiceActivityProposal`. The local owner validates that the partition:

- begins at exactly Shot-relative zero;
- contains no gap;
- contains no overlap;
- alternates speech/silence states after adjacent same-state merging;
- ends at the authoritative exact Shot duration;
- carries finite confidence for the stated class.

Only after validation does the owner map ranges to original Asset rational time and atomically persist the full evidence batch.

## Probability and confidence rule

The first transparent baseline deliberately avoids pretending that thresholded timestamps are mathematical truth.

For every 512-sample model window:

```text
p = Silero speech probability

if p >= threshold:
    class = speech
    class_confidence = p
else:
    class = silence
    class_confidence = 1 - p
```

Adjacent equal classes are merged. Their confidence is the valid-sample-weighted mean of the per-window class confidence.

The default prototype threshold is `0.5`.

This is a deliberately simple Engineering baseline. Hysteresis, minimum speech/silence duration, padding, or other segmentation policy may be benchmarked later. Any behavior change must change `provider_revision`; it must not silently overwrite evidence from the current producer version.

## Atomic partition persistence

Voice activity is semantically one complete speech/silence partition, so its evidence rows are persisted in one SQLite transaction.

If one immutable record conflicts, the whole new batch rolls back. A half-written VAD result must never be observable as if missing spans meant factual silence/speech absence.

For the same exact Shot plus `provider_id + provider_revision`, a changed partition is rejected as nondeterministic. A genuine algorithm/model/policy change must use a new producer revision.

## Audio decoding

The prototype owns a minimal provider-internal FFmpeg decoder:

- exact requested Shot clip only;
- mono;
- 16 kHz;
- signed 16-bit little-endian PCM;
- streamed in 512-sample windows;
- final partial window zero-padded for inference only;
- no whole-clip raw-audio buffering.

No decodable audio is **not** converted into fake silence evidence. It produces an unavailable/error result instead.

A small decode-length difference up to one Silero window may be reconciled by ending the final proposal span at the authoritative Shot duration. Larger mismatch is rejected.

## Runtime-version policy

ONNX Runtime v1.29.0 was released on 2026-08-12 and includes Windows x64 artifacts, but a same-day release is not automatically treated as the validated baseline.

The Windows Engineering Probe should compare a known-working 1.28.x release and v1.29.0 before exact runtime approval. The selected version, resolved NumPy version, wheel provenance, and model file SHA-256 must be recorded by the Probe.

## Benchmark gate still open

Before this VAD path becomes `DIRECT-APPROVED`, verify on Windows x86-64:

- FFmpeg Shot-scoped PCM decode;
- NumPy + chosen ONNX Runtime installation;
- pinned model acquisition and exact file SHA-256;
- model load time;
- CPU VAD wall time / real-time factor;
- bounded memory behavior;
- raw probability availability;
- speech/silence full partition construction;
- exact Shot-relative → original Asset time mapping;
- all-silence speech fixture behavior;
- speech fixture behavior;
- no-audio behavior remains unavailable rather than fabricated silence;
- no hidden network dependency during normal analysis.

No paid Product Probe is justified for these engineering questions.
