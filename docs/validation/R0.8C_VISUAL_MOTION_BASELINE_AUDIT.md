# R0.8C Visual Motion Engineering Candidate

**Status:** ENGINEERING CANDIDATE — not DIRECT-APPROVED  
**Date:** 2026-08-13  
**Capability:** Visual Temporal Evidence  
**Architecture authority:** `CAP-03_MEDIA_UNDERSTANDING_SPEECH_TEMPORAL.md`

## 1. Purpose

Establish the first CPU-capable visual-temporal measurement path required by R0.8:

```text
exact Shot
→ distributed feature tracking
→ robust global camera transform
→ camera-motion measurement
→ camera-compensated residual local-motion measurement
```

This batch answers a mechanism question:

> Can the system measure global camera motion separately from residual local motion without crossing Shot boundaries?

It does **not** answer:

> What semantic action happened, which source window should be edited, or where the final cut belongs?

Those authorities remain outside this batch.

## 2. Candidate runtime

First isolated Windows candidate:

```text
package: opencv-python-headless
version: 4.13.0.92
execution: CPU
Python target: 3.12
normal use: local-only; no network inference
```

This is intentionally not the newest available OpenCV major release. The project stable-first policy favors a mature 4.x candidate before considering a recent major-version jump without evidence.

Do not add this dependency to the production lock merely because the Engineering Probe needs it. First validate the mechanism in an isolated environment, record the actual wheel/runtime identity, and then decide adoption.

## 3. Initial algorithm candidate

Use interpretable classical measurements first:

```text
gray frame pair
→ distributed trackable features
→ pyramidal Lucas-Kanade sparse optical flow
→ valid correspondence set
→ robust limited-affine global transform with RANSAC
→ predicted global displacement
→ per-track residual displacement
```

The exact tuning parameters are benchmark variables, not Domain truth.

The first transform model should be limited enough to remain interpretable. Do not jump directly to a high-flexibility model merely to fit every correspondence.

## 4. Provider / owner boundary

OpenCV is an implementation provider, not Domain authority.

Preferred ownership shape:

```text
VisualMotionPort
→ Shot-relative VisualMotionProposal
→ local deterministic validation
→ ArtifactStore for rich versioned measurement payload
→ TemporalEvidence summaries bound to exact Shot revision
```

The concrete OpenCV implementation belongs behind the provider seam, preferably under `providers/vision/`.

The owner/service belongs in the media capability layer and must load the exact Shot and resolve its exact Asset revision before accepting a proposal.

No OpenCV type, NumPy array, FFmpeg path, or provider-specific enum belongs in Domain entities.

## 5. Exact Shot boundary

Motion computation must be Shot-scoped.

The frame decoder/request must receive the authoritative Shot `source_range` and must not compare:

- a frame before Shot start;
- a frame after Shot end;
- frames from adjacent Shots.

Existing bounded-memory FFmpeg RGB24 code may be generalized/reused, but a full-Asset decode followed by accidental cross-Shot pairing is not acceptable.

All committed source times remain rational `MediaTime` / `MediaTimeRange`.

## 6. Evidence semantics

First-batch evidence may include kinds such as:

```text
camera_motion_measurement
residual_motion_measurement
```

Names may be refined during implementation if they remain semantically equivalent and provider-neutral.

This batch must **not** emit:

```text
subject_action
action_start
action_stop
meaningful_action
```

Raw or residual motion is not semantic action.

This batch also must not create final `TemporalAnchor` objects. Anchor extraction belongs to a later coherent batch after the measurement mechanism is proven.

## 7. Rich measurement payload

The generic `TemporalEvidence` schema should not be inflated with OpenCV-specific numeric fields.

Persist the rich deterministic measurement record as a content-addressed JSON Artifact when useful. A record should preserve enough provenance to reproduce/audit the result, including where available:

- exact Shot revision;
- frame/sample source times;
- frame geometry / sampling rate;
- provider/runtime revision;
- feature count;
- tracked correspondence count;
- spatial feature coverage;
- robust-fit inlier count / ratio;
- selected transform model;
- transform parameters;
- reprojection/residual fit error;
- global displacement measure;
- residual local-motion statistics;
- explicit unavailable/weak-fit reason when estimation is insufficient.

`TemporalEvidence.artifact_refs` may point to the stored rich record while the evidence itself remains a compact, durable summary.

Do not invent a fused confidence formula merely to fill the field. Any confidence mapping introduced in this batch must be simple, explicit, tested, and justified by observable fit quality; otherwise use the narrowest defensible representation and record the limitation.

## 8. Controlled Engineering fixtures

At minimum prove four cases inside exact Shot boundaries:

### A. Static scene

Expected:

- near-zero global motion;
- near-zero residual motion.

### B. Global pan / translation only

Expected:

- material global motion;
- camera compensation removes most coherent motion;
- residual local-motion signal remains low;
- absolutely no semantic local-action evidence is emitted.

### C. Local object motion, static camera

Expected:

- global transform remains near static or is rejected as weak if background evidence is insufficient;
- residual local-motion signal is materially present.

### D. Global pan + independent local object motion

Expected:

- coherent camera motion is estimated;
- independent object motion remains in residual evidence after compensation.

Fixtures may be synthetic/controlled because this is an Engineering Probe. Product-quality claims require later real footage.

## 9. Failure / quality semantics

The system must explicitly distinguish:

```text
measurement available
weak global fit
insufficient features
tracking failure
decode failure
```

Do not reinterpret an unavailable transform as zero camera motion.

Do not reinterpret a low residual value as proof that no semantic action occurred.

Do not silently fall back from failed global compensation to raw whole-frame motion and label it local action.

## 10. First Engineering gate

Before this candidate is approved, collect at least:

- Windows x86-64 / Python 3.12 install and exact runtime version;
- actual candidate wheel/package provenance;
- exact Shot-scoped FFmpeg decode behavior;
- bounded-memory behavior;
- static fixture result;
- pan-only fixture result;
- local-motion fixture result;
- pan + local-motion fixture result;
- global fit quality diagnostics;
- evidence that no computation crosses a Shot boundary;
- evidence/artifact persistence and SQLite reopen where committed;
- CPU wall time / real-time factor on controlled short fixtures;
- full repository Quality Gate.

The decisive negative-control requirement is:

> A pure camera pan must not become a false local-action anchor or semantic action claim.

No paid Product Probe is justified for this mechanism gate.

## 11. Explicitly out of scope

Do not include in this first batch:

- semantic action classification;
- VLM action timestamp requests;
- seeded object/product tracking across a Shot;
- motion onset/peak/settle TemporalAnchor extraction;
- coarse-to-fine refinement policy;
- embeddings/vector retrieval;
- Director;
- Resolver;
- EDL decisions;
- Auto Reframe.

Those remain subsequent Roadmap work.
