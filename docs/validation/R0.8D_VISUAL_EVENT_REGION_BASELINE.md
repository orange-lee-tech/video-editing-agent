# R0.8D Visual Event Reduction + Coarse Anchor Baseline

**Status:** ENGINEERING BASELINE — implementation pending  
**Date:** 2026-08-13  
**Phase:** R0.8 — Media Evidence Foundation  
**Authority:** Product Constitution v1.0 → Architecture Contract v0.2 → CAP-03 → Roadmap V2

## 1. Strategic purpose

R0.8C proved the first local CPU measurement mechanism:

```text
exact Shot
→ sparse feature tracking
→ robust global camera transform
→ camera-compensated residual motion
```

The next problem is not another perception model. The next problem is turning dense measurement data into durable, low-density, reusable temporal evidence.

R0.8D therefore owns:

```text
persisted visual-motion measurement set
→ deterministic signal normalization
→ event-region reduction
→ coarse onset / peak / settle anchors
```

It still does **not** own semantic action meaning or edit selection.

## 3. Problem A — Artifact rehydration

`TemporalEvidence.artifact_refs` intentionally stores opaque artifact IDs, but the current `ArtifactStore` read path requires a full `StoredArtifactRef`.

A downstream evidence reducer must not bypass the ArtifactStore abstraction and reconstruct filesystem paths itself.

Add the narrowest general read seam required by persisted evidence, preferably:

```text
ArtifactStore.get_by_id(artifact_id) -> bytes
```

Requirements:

- validate `art_sha256_*` identity;
- derive the expected digest from identity;
- read through the storage implementation;
- verify SHA-256 integrity before returning bytes;
- missing/corrupt content fails explicitly;
- existing `get(StoredArtifactRef)` semantics remain valid;
- no media-specific logic enters ArtifactStore.

Do not add filesystem paths to Domain entities.

## 4. Problem B — lifecycle ownership

The visual-motion JSON Artifact is durable derived evidence, not a disposable frame cache.

When it is committed by the visual-motion owner, register lifecycle metadata using the existing artifact lifecycle seam:

```text
retention_class = DURABLE_DERIVED_EVIDENCE
purpose = visual_motion_measurement
source = exact Shot revision
```

Reuse the existing `ArtifactLifecycleRepository`. Do not invent a parallel retention registry.

## 5. Problem C — raw evidence density

The R0.8C prototype currently emits two durable `TemporalEvidence` rows for every available frame pair. The controlled 3-second probe therefore produced 58 evidence rows.

That shape must not become the long-video architecture.

Rich frame-pair measurements belong in the content-addressed motion Artifact.

For new R0.8D-era writes, prefer one compact measurement-set evidence record per exact Shot/proposal, for example:

```text
kind = visual_motion_measurement_set
source_range = exact Shot range in original Asset time
artifact_refs = [motion artifact id]
```

The exact name may change if an equivalent provider-neutral name is clearer.

Its confidence must describe only a transparent measurement-quality/completeness property. It must not be interpreted as action probability.

Do not silently rewrite or delete historical evidence rows. New behavior may coexist with old persisted records through explicit compatibility handling if needed.

## 6. Event-region reducer

Build a deterministic media-layer reducer that consumes an **explicitly selected** visual-motion measurement-set evidence identity.

Do not silently choose "latest" when multiple provider revisions/artifacts exist.

The reducer must:

1. load the exact Shot revision;
2. load/validate the selected measurement-set evidence;
3. retrieve its Artifact through `ArtifactStore.get_by_id`;
4. decode the provider-neutral persisted `VisualMotionProposal`/measurement payload;
5. verify Shot/provider/provenance consistency;
6. derive camera and residual motion signals;
7. reduce dense intervals into contiguous candidate event regions;
8. persist region evidence atomically before anchors reference it.

## 7. Provider-neutral motion signal

Do not compare raw pixel displacement across arbitrary frame sizes/FPS as if it were universal truth.

For event reduction, normalize displacement against both frame geometry and interval duration, for example:

```text
normalized_rate
= displacement_pixels
  / frame_diagonal_pixels
  / interval_seconds
```

Equivalent dimensionless/time-normalized formulations are acceptable if documented and tested.

The chosen formula belongs to deterministic media policy, not Domain truth.

## 8. Threshold / hysteresis policy

Thresholds remain Engineering/benchmark variables.

Do not freeze an unexplained product threshold into Domain entities.

Use an explicit policy/config object for at least:

- camera event enter threshold;
- camera event exit threshold;
- residual event enter threshold;
- residual event exit threshold;
- minimum region duration/interval count;
- maximum mergeable quiet gap where applicable.

A hysteresis-style reducer is preferred over one-frame spike labeling.

No automatic threshold lowering is allowed merely to make a fixture pass.

## 9. Region evidence semantics

Allowed first region kinds:

```text
camera_motion_region
residual_motion_region
```

Equivalent provider-neutral names are acceptable.

A residual-motion region is **not** a `subject_action`.

A camera-motion region is **not** automatically a pan/tilt/zoom semantic classification.

Region evidence should reference:

- the exact Shot;
- the selected raw measurement-set evidence;
- the underlying motion Artifact;
- the reducer method/version;
- an explicit reliability measure.

## 10. Coarse TemporalAnchor semantics

For every accepted region, the first deterministic anchor baseline may emit:

```text
camera_motion_onset
camera_motion_peak
camera_motion_settle

residual_motion_onset
residual_motion_peak
residual_motion_settle
```

Anchors are candidate facts, not edit commands.

Rules:

- onset: beginning of the accepted coarse region;
- peak: time associated with the strongest normalized signal inside the region;
- settle: end of the accepted coarse region;
- all times remain original Asset `MediaTime`;
- all anchors reference the region evidence that supports them;
- no anchor may escape the exact Shot;
- ties must resolve deterministically;
- confidence must remain measurement/reducer reliability, not semantic-action probability.

Do not call these final/native-FPS exact anchors. They are the coarse baseline that later refinement may improve.

## 11. Explicitly out of scope

Do not add in R0.8D:

Those are later coherent batches.

## 12. Deterministic Engineering fixtures

At minimum cover:

### Static

Expected:

- no camera region;
- no residual region;
- no motion anchors.

### Pan only

Expected:

- camera region may exist;
- residual local-motion region must not be fabricated from coherent camera motion;
- no residual onset/peak/settle anchors.

### Local only

Expected:

- residual region exists for the controlled moving target;
- residual onset/peak/settle are ordered and remain inside the known event neighborhood.

### Pan + local

Expected:

- camera region and residual region can coexist;
- residual event remains after compensation.

### Two separated local-motion bursts

Expected:

- two regions remain distinct when the quiet gap exceeds merge policy;
- anchor identities/order are deterministic.

### Weak/unavailable measurement interval

Expected:

- unavailable measurement is not converted to zero motion;
- reducer handles the gap explicitly according to policy;
- no fabricated anchor crosses unsupported time.

## 13. Persistence / restart

Prove:

```text
motion Artifact
→ measurement-set TemporalEvidence
→ event-region TemporalEvidence
→ TemporalAnchor
→ close project
→ reopen
→ exact equality / provenance retained
```

Also prove that Artifact content can be rehydrated by identity after restart without caller filesystem knowledge.

## 14. Density gate

The durable structured-evidence row count must be based on:

```text
measurement sets + accepted event regions + anchors
```

not directly proportional to every frame pair.

The rich dense sequence may remain in the content-addressed Artifact.

This is an architectural gate, not merely a performance optimization.

## 15. Engineering exit gate

R0.8D is adequate when:

- hardened R0.8C Windows probe is reconfirmed;
- Artifact identity rehydration is safe and integrity-checked;
- motion Artifact lifecycle is durable-derived-evidence;
- new raw persistence is low-density;
- static negative control produces no regions/anchors;
- pan-only does not produce residual local-motion regions/anchors;
- local and pan+local controlled fixtures produce the expected residual regions;
- multiple bursts remain separable;
- exact Shot/rational-time boundaries survive restart;
- Quality Gate is green;
- no semantic/edit authority was introduced.

No paid Product Probe is required for this deterministic signal-reduction batch.
